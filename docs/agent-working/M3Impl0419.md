# M3 Implementation Note

Date: 2026-04-19

## Goal

Implement the M3 frontmatter-driven site behavior and collection contract so
MoonInk build output owns:

- draft exclusion;
- search-only exclusion via `search: false`;
- deterministic homepage/search/tags/series/archive ordering;
- typed site author/profile metadata;
- shared card data across public surfaces;
- generated system pages for `search`, `tags`, `series`, and `archive`.

## Design Decisions

- Frontmatter now treats `draft`, `featured`, `pinned`, `search`, and `toc` as
  typed behavior fields with explicit `check` diagnostics on scalar/type
  mismatches.
- `layout` is author-facing and closed to `article`, `page`, and `home`; the
  build normalizes `home` to the internal `index` layout key.
- Site-level author/profile metadata is typed in `moonink.json` under `author`
  and is now used by homepage author presence, article author cards, and search
  / collection card labels.
- Source-backed pages are filtered through a published-build view before
  collection assembly so `draft: true` is excluded from HTML, search, and
  generated system pages.
- Shared card construction is centralized in `src/cli/site_surfaces.mbt` and is
  reused for homepage modules, search cards, tag pages, series pages, archive
  groups, and search-index ordering.
- Theme V2 generated system surfaces prefer dedicated layout keys
  (`search`/`tag`/`series`/`archive`) but are allowed to fall back to `page` so
  older test fixtures and bundles remain buildable.

## Current Limitations

- The built-in `/search/` page currently performs client-side filtering over the
  emitted card dataset embedded in the page, while `search-index.json` remains
  the canonical external search artifact.
- Generated system pages are not inserted into auto-navigation by default.
- Homepage modules are currently a built-in default composition rather than a
  fully typed configurable module system in `moonink.json`.

## Next Steps

- Promote homepage module composition from built-in defaults into a typed site
  contract when the product surface needs more than featured/recent defaults.
- Decide whether generated system pages should become first-class navigation
  nodes or stay discoverable via header links, cards, and future theme config.
- Consider whether the built-in search page should hydrate directly from
  `search-index.json` once a richer client-side search/runtime contract is
  needed.
